# Инфраструктура ML-проекта

Домашнее задание №1. Проект создан через `uv init --lib` со структурой `src/`.
Python зафиксирован на 3.12.8; зависимости и версии инструментов — в `uv.lock`.

## Установка и запуск

Требуются macOS или Linux, Git, make, curl и доступ к интернету при первом запуске.
После клонирования перейдите в корень репозитория:

```sh
make setup
make check
make demo
```

`make setup` автоматически устанавливает uv, если он отсутствует, загружает нужный Python,
создаёт `.venv`, устанавливает зависимости строго по lock-файлу и подключает pre-commit.
Активация окружения не требуется. Повторный запуск безопасен.

| Команда | Назначение |
| --- | --- |
| `make setup` | Поднять окружение и установить хуки |
| `make check` | Проверить стиль, форматирование и типы без исправлений |
| `make hooks` | Запустить все хуки на всём проекте |
| `make demo` | Запустить демонстрацию; результат `Accuracy: 75.00%` |

## Структура

- `src/ml_product_infrastructure/` — типизированный код проекта и расчёт accuracy.
- `scripts/debug_checks.py` — отладочный скрипт с аннотированной функцией.
- `scripts/uv.sh` — автоматическая подготовка uv для чистой машины.
- `.github/workflows/checks.yml` — проверки pull request и main в GitHub Actions.
- `docs/` — история работы с ветками и инструкция по защите main.

## Проверки

Ruff 0.14.0: длина строки 99, дополнительные группы B, UP, I, SIM;
F401 игнорируется в `__init__.py`. Форматтер запускается только с `--check`.
Mypy 1.18.2 работает в strict-режиме. Исключение для отсутствующих аннотаций
задано только для стороннего pandas; собственные импорты и функции проверяются строго.
Pre-commit 4.3.0 запускает инструменты из того же lock-файла, что и `make check`.
Все три хука выполняются на каждом коммите и возвращают ошибку при нарушениях.

Для проверки испортите тип аргумента в `scripts/debug_checks.py` или добавьте
неиспользуемый импорт: `make check` и попытка коммита должны завершиться с ошибкой.
Перед продолжением восстановите корректный код.

Ветка main защищена: все изменения принимаются через pull request, включая изменения владельца.
Обязательная проверка для слияния — `quality`. Подробности: `docs/github.md`.
История fast-forward, merge-коммита и разрешения конфликта: `docs/branch-history.md`.
