# Завершение работы на GitHub

Этот файл описывает оставшуюся внешнюю часть задания. Наличие инструкции само по себе
не означает, что удалённый репозиторий, защита и pull request уже созданы.

1. Создать пустой репозиторий GitHub и подключить его как origin.
2. Опубликовать исходный коммит main до включения защиты.
3. Создать ветки A и B от исходного коммита, добавить в каждую отдельный коммит.
4. В main выполнить `git merge --ff-only A`, затем `git merge --no-ff B`.
5. В отдельной ветке изменить ту же строку, что затем будет изменена в main.
   Выполнить слияние, вручную разрешить конфликт и сохранить merge-коммит.
6. Опубликовать main и учебные ветки. Сохранить их для просмотра истории.
7. Дождаться первого успешного запуска GitHub Actions, чтобы проверка `quality`
   появилась в настройках обязательных проверок.
8. В Settings → Branches → Add classic branch protection rule для `main` включить:
   - Require a pull request before merging;
   - Require status checks to pass before merging → `quality`;
   - Require branches to be up to date before merging;
   - Require conversation resolution before merging;
   - Do not allow bypassing the above settings.
   Не разрешать force push и удаление ветки. Не требовать одобрения второго человека
   для личного учебного репозитория. Не включать линейную историю: нужны merge-коммиты.
9. После сохранения защиты изменения в main вносить исключительно через pull request.
10. Создать ветку с полезным изменением документации, открыть PR, дождаться зелёных
    проверок и слить его. Для сдачи нужны URL репозитория и этого влитого PR.

Защита веток зависит от тарифа GitHub и видимости репозитория. Если она недоступна
для приватного репозитория, согласовать публичную видимость или подходящий тариф.
